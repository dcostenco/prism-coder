WHAT THE REVIEW CHANGED, AND WHY THIS IS NOT A ROUND-BY-ROUND LOG
═══════════════════════════════════════════════════════════════════

This section used to enumerate every review round. That was a mistake with a
tidy proof: each new round made the enumeration stale, so the next round
correctly reported the log as a defect, and fixing it started another round.
The log was generating the findings that justified it. It is gone.

What matters is what the review changed, which does not go stale:

TWO GRADERS WERE WRONG and are fixed. prose:nofabricate asked only whether an
answer contained a hedge, never whether it also contained a number, so a hedge
beside an invented one scored correct on the one task built to catch exactly
that. prose:onesentence shared a 48-token budget that cut every answer before a
second sentence could appear, so it measured truncation and reported it as
history carry-over; it also missed a terminator followed by a closing quote.

THE FABRICATION GUARD took five attempts because each was a list. A shape
needing 8 characters missed "5550100". A punctuation list missed "555,0100".
An ASCII character class missed non-Latin numerals. It counts digits now, where
a separator is anything that is not a letter, expressed in Unicode classes.
Nothing is enumerated, so there is no next item to miss.

MY OWN CLAIMS WERE THE LARGEST CATEGORY. The document asserted the grader fails
any answer containing a number; it does not. It named a punctuation set the code
never implemented. It called a column an upper bound when the graders err in
both directions. It said the self-test covers every grader when it covers four
of twenty-two. It drew causal conclusions from three confounded layouts. And it
called a correct clinical answer confused, then built a test case on that
judgement, because I read the answer without re-reading the definition it was
answering. Every one of those is corrected in place, saying what the earlier
wording got wrong rather than editing it away.

THE LESSON, which is the reason any of this is written down: most of what the
later cycles found was prose I had written to explain the previous fix, and a
review with no stated exit criteria will find that forever, because it is
always there.

An earlier version of this paragraph said the code "stopped producing defects
well before the review did". That is false. The averaging fix, which counted a
failed generation as zero tokens and understated the column, was a real code
defect found in the FIFTEENTH cycle. Code defects kept arriving late; they were
simply outnumbered by prose ones.

WHAT WAS DELIBERATELY NOT FIXED, AND WHY. Four limits are asserted in
--self-test rather than chased:

  - Digits spelled as words ("five five five zero one zero zero") are missed.
  - Vanity numbers ("1-800-FLOWERS") are missed: their digits are carried by
    LETTERS, so no separator rule reaches them. Two things would catch them: a
    phone-shaped special case, which is precisely what this guard was rewritten
    to stop being and where every previous special case produced the next hole;
    or a word-to-digit parser, which is real but disproportionate machinery for
    a benchmark grader and would carry its own false positives into the one
    task whose job is detecting them.
  - Labelled groups ("area code 555, exchange 010, line 0000") are missed: the
    words between the groups end each digit run before it reaches seven. Same
    category as the vanity number — digits interrupted by letters.
  - A date carries 7+ digits, so a decline mentioning one is called fabricated.

The adversary here is a local model answering a question, not someone crafting
a bypass. The false alarm errs in the safe direction: it turns the control red
and gets looked at, where a miss would be published as a passing score. None of
this makes prose:nofabricate a phone-number validator, and a `correct` verdict
on it is not a safety guarantee.

RUN AGREEMENT, and exactly what backs it. The table above comes from ONE run,
the last one, and its untruncated answers are the committed sidecar it names.
That single run is the only part of this a reader can audit in the working
tree. Earlier commits on this branch carry their own sidecars, so git history
holds several more, each from the file as it stood at that commit.

Every run made while fixing this produced the same verdicts, and only avg_ms
moved. That is a note from the author. It is not an auditable artifact, the
count is not reproducible from the tree, and no number is given here for it
because a number would imply a precision the evidence does not carry.

WHAT WAS OBSERVED, stated as observation. On this model snapshot the format
constraint was honoured in the one layout where it sat inline in the same
sentence flow as the ask, and ignored in the two layouts where it sat in a
separate block. System and prompt placement were both ignored. Three layouts,
three repetitions each, temperature 0.

WHAT THAT DOES NOT ESTABLISH. It does not establish that block separation is
the CAUSE. The inline layout differs from the other two in more than block
separation — token distance, the absence of an intervening newline and the
constraint's position relative to the question all move together, and nothing

in what they ask for, so the comparison does not isolate it.

Treat constraint:prefix as a documented limitation of this model snapshot, not
a product bug. Do not chase it by moving text onto one line: that fits a
measured quirk of one snapshot, and nothing here establishes whether it holds
